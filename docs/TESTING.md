# Testing

Verification is layered so that everything provable without hardware is proven, and the
device-only gaps are stated plainly rather than implied.

## Run the tests

- **In Unity:** Window → General → Test Runner → EditMode → Run All.
- **Headless:** close the Editor, then

  ```powershell
  & "C:\Program Files\Unity\Hub\Editor\6000.6.2f1\Editor\Unity.exe" `
    -batchmode -runTests -projectPath "D:\Schl-sselbild" `
    -testPlatform EditMode -logFile -
  ```

- **Through Unity MCP (what we used):** an `mcp-unity` `run_tests` call with
  `testMode: EditMode`. Example result: `111/111 passed - 0 failed`.

Current state: **111 / 111 EditMode tests pass, 0 warnings.**

## What is covered

| Area | Count | Examples |
|------|-------|----------|
| Crypto + key | 28 | GCM known-answer vectors (NIST SP 800-38D / CAVP), tamper and wrong-key fail, blob layout, random nonce, hex/base64 key parsing. |
| QR + page | 52 | Envelope split/reassemble (order-independent, missing/duplicate/inconsistent rejected), encode/decode round-trips, **Python fixture pages decode to the exact secrets**, wrong key fails, compose/decode round-trip. |
| Capture | 7 | `FrameDecoder` decodes fixture pages (texture and `Color32[]`), downscale variants, wrong key throws. |
| UI logic | 24 | `AppSettings` defaults/clamping/persistence/events, `KeypadModel` editing, `UiTheme` status mapping and colourblind variants. |

Fixtures live in `Assets/Schlusselbild/Tests/EditMode/Fixtures/`
(`page_short.png`, `page_multi.png`, `key.hex`, `secret_short.txt`, `secret_multi.txt`),
generated by the legacy Python oracle and committed.

## Cross-platform (byte) compatibility

- **Python → Quest:** the fixture tests decode pages composed by the Python implementation
  and decrypt them with the fixture key. This is the gating evidence for format fidelity.
- **Quest → Python:** the Quest `PageComposer` output was written to a PNG and decoded by the
  Python oracle (`legacy/python`), recovering the exact secret. Reproduced with the
  `Schlusselbild / Dev / Export Interop Page` menu item plus a Python decode.

## Not verified (needs hardware)

- **Real passthrough scanning** — `Meta.XR.PassthroughCameraAccess` is device-only; in the
  Editor the Scan screen reports the camera is unavailable.
- **Real controller/hand clicks** — the input path is the official `OVRInputModule` +
  `OVRRaycaster` and is error-free, but an actual trigger press must be confirmed on the
  headset or in the Meta XR Simulator.
- **IL2CPP runtime behaviour of the managed GCM** on device (the APK builds; runtime not yet
  exercised on hardware).

## Regression guards

- The ordering bug where all screens rendered at once (see `DECISIONS.md` D13) is guarded by
  keeping navigation in one place (`AppController.Show` + `HideAll`).
- The build is kept warning-free so new deprecations surface immediately.
